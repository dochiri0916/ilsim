# 일심 작업 절차

1. 요청이 코드·문서 변경이면 `start_task`에 사용자 요청 원문을 넘긴다. 질문·설명 요청이면 작업을 만들지 않고 답만 한다.
2. 돌려받은 단계 지시대로 허용된 경로만 고친다. 진행 중인 작업이 있으면 `next_step`으로 현재 지시를 받는다.
3. 단계를 마치면 `submit_result`를 호출한다. 실패하면 지적된 부분만 고치고 다시 제출한다.
4. 요구사항·테스트 케이스 단계는 사용자 승인이 있어야 다음으로 간다. 산출물을 요약해 보여 주고 승인 여부를 묻는다. 사용자가 승인한다고 말하면 `approve_stage`, 고칠 점을 말하면 `reject_stage`(사유)를 호출한다. 사용자가 답하기 전에는 호출하지 않는다. 호출하면 앱이 사용자에게 다시 확인받는다.
5. git commit·push·브랜치 변경은 하지 않는다. 커밋은 일심이 단계를 통과할 때 한다.
6. 사용자에게 보고할 때 단계 결과와 검증 결과를 함께 알린다.
