# 생활 체조 컨벤션

`domain`·`application`·`adapter` 코드에 적용한다. 어댑터는 프레임워크 제약이 있는 곳(JPA Entity, DTO)을 예외로 한다. 클래스·파라미터 선언과 의존성 주입은 [공통 코드 컨벤션](coding-conventions.md)을 따른다.

- 메서드의 들여쓰기는 한 단계까지만 허용한다.
- `else`를 사용하지 않고 early return으로 분기를 정리한다.
- VO 적용 기준과 메타데이터·상태 enum의 예외는 [도메인 컨벤션](domain-conventions.md)을 따른다.
- 도메인·애플리케이션의 컬렉션은 일급 컬렉션으로 감싼다. Command·Query·Result와 출력 포트의 계약도 포함한다. 웹 Request·Response, 공개 통합 이벤트 등 외부 계약과 어댑터 내부 변환용 지역 변수는 원시 컬렉션을 허용한다. 외부 계약의 컬렉션은 방어적으로 복사하고 변경 가능한 내부 컬렉션을 노출하지 않는다. 계층별 작성 규칙은 [도메인](domain-conventions.md)·[애플리케이션](application-conventions.md) 컨벤션을 따른다.
- 한 줄에 점(`.`)을 하나만 사용한다. 빌더·스트림·`Optional` 체이닝은 예외다.
- 이름을 줄이지 않는다. `id`, `dto`처럼 널리 쓰이는 약어는 예외다.
- 클래스와 메서드는 단일 책임을 갖게 한다. 줄 수로 제한하지 않으며, 책임이 하나라면 길어도 분리하지 않는다. 한 메서드에서 파싱·업무 규칙·응답 변환을 함께 하면 분리한다.
- 서비스·정책·어댑터의 의존 객체는 5개 이하를 지향하고, 초과하면 책임 분리를 검토한다. 도메인 객체의 필드 수는 제한하지 않는다.
- 객체의 상태를 꺼내 바깥에서 업무 판단을 하지 않고, 판단은 해당 객체의 메서드로 제공한다(Tell, Don't Ask). 접근자는 `id()`처럼 `get` 없이 이름만 쓰고, `setXxx`는 두지 않는다.
