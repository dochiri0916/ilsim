# DB 변경 가이드

기존 DB의 컬럼·제약·타입을 변경할 때 적용한다. 목표 스키마는 [영속성 컨벤션](persistence-conventions.md)을 따른다.

- 기존 DB는 애플리케이션 시작 전에 컬럼과 제약을 변경한다. `ddl-auto=update`는 컬럼 이름 변경을 대신하지 않는다.
- 자동 생성된 기존 유니크 제약명은 Entity 선언과 맞추고, 동일 컬럼의 제약을 중복으로 추가하지 않는다.
- 유니크 제약 추가 전에는 중복 데이터를 확인한다.
- 기존 DB의 상태 컬럼이 enum 타입이면 문자열 매핑과의 호환성을 확인한다.
