# 주문·재고 정의서 예제

버전: sample-v1

이 문서는 형식 검증용 가상 요구사항이다. 실행 가능한 주문 서비스나 기존 샘플의 구현 계약이 아니다.
동일한 MySQL DB에 주문과 재고를 저장하는 설계를 전제로 한다.

## 도메인과 입력

Order는 주문 데이터를, Inventory는 재고 수량을 소유한다.
주문 application service는 Inventory의 공개 재고 차감 기능을 호출할 수 있다.
진입점의 구현 방식은 아직 미정이다. 수량은 양수이며 비즈니스 키는 tenantId/orderId이다.

## 정상 처리와 불변 규칙

재고는 음수가 될 수 없으며 주문 저장과 재고 차감은 함께 성공하거나 롤백된다.
재고 5개에서 수량 2개를 요청하면 주문 1건이 저장되고 재고는 3개가 된다.
업무 transaction 안에서 외부 변경 호출을 하지 않는다.

## 중복 처리

성공한 동일 키·동일 입력의 재처리는 최초 결과를 반환하며 추가 차감하지 않는다.
동일 키의 다른 입력은 conflict로 거부하고 기존 주문과 재고를 변경하지 않는다.
멱등 키 보관 기간과 기간 만료 후 재전달 계약은 아직 결정하지 않았다.

## 동시 처리

재고 1개에서 서로 다른 키의 수량 1개 주문 두 건이 경쟁하면 한 건만 성공한다.
다른 주문은 재고 부족 오류로 거부되고 변경을 남기지 않는다. 최종 재고는 0개이다.

## 실패 처리

재고 차감 이후 주문 저장 실패 시 새 주문을 남기지 않고 재고를 원래 수량으로 복구한다.
재고 5개에서 수량 2개 차감 이후 실패하면 주문은 0건이고 재고는 5개이다.
commit 이후 동일 입력 재시도는 추가 변경을 남기지 않는다.

## 미승인 대안 A — 충돌 예제 전용

주문 저장 실패 시에도 재고 차감을 유지한다.

이 문장은 기본 실패 처리와 의도적으로 충돌한다. 정상 예제는 채택된 기본 계약을 분석하고,
conflict 예제는 미승인 대안까지 함께 검토하여 CONTRADICTED로 기록한다.
JSON Schema가 이 문장의 업무적 충돌을 자동 탐지한 것은 아니다.
